# kobi

一个**纯本地运行**的安卓课程表应用。

核心价值只有一句话：**每节课开始前 1 小时，把下节课的课程名与地点推到手机通知栏。**

不联网、不注册、不上传任何数据。所有课表数据只存在手机本地的 SQLite 里。

---

## 功能

| 模块 | 功能 |
|---|---|
| 课程数据 | 增删改查、多时段（一门课可有多个上课时段） |
| 数据管理 | 一键重置全部课程数据、单条删除、多选批量删除 |
| 周次 | 周次范围 + 单双周（内部用位掩码表示，决定某周是否有课） |
| 今日日期 | 周课表与列表页显示今天的具体日期与当前教学周 |
| 冲突检测 | 同一天、节次重叠、周次相交时给出提示（**只提示不阻止**——大学课表本身存在合法冲突） |
| 批量导入 | CSV、粘贴课表纯文本、`.ics` 日历文件、**图片识别（离线 OCR，不联网）** |
| 周课表网格 | 时间 × 星期，支持连堂课程跨节次合并 |
| 列表视图 | 按「今天 / 明天 / 本周」分组 |
| 定时提醒 | 课前 1 小时准点触发（核心） |
| 通知呈现 | 动态倒计时 / 分段进度 / 自定义布局 三种样式 |
| 权限自愈 | 权限自检面板、开机重排闹钟 |

### 明确不做

- **教室路线指引**：通知中只展示教室文字信息，不做路线跳转。
- 教务系统自动抓取：需要上交教务账号密码，与《个人信息保护法》冲突，且有法律风险。
- 小米超级岛接入：需要企业资质与逐场景审核，个人开发者基本走不通。
- 常驻后台保活：违反应用商店生态政策，且厂商后台策略本身禁止。

## 导入课表

四种来源，都在「导入」页：

| 来源 | 说明 |
|---|---|
| CSV 表格 | 首行为表头，顺序固定：`课程名,教师,地点,星期,起始节次,结束节次,周次` |
| 粘贴文本 | 每行一门课，行内先认周次、再认节次、再认星期，剩下的按特征归类到课程名/教师/地点。示例：`高等数学 周一 1-2节 1-16周 教学楼A101` |
| `.ics` 日历 | 把日历里的钟点时间按内置作息表换算成节次 |
| **图片识别** | 选一张课表截图，离线识别出文字并**回填到文本框**，你核对后再点「解析并导入」 |

关于图片识别：识别在**本机完成**，图片不会上传到任何地方；识别结果只是文本，**必须由你核对后**才会入库。识别精度受图片清晰度、拍摄角度、表格线影响，竖排或手写体识别率低。

关于合并规则：导入时**同名同教师**的记录会合并为**一门课程**（多个时段挂在同一门课下），重复的时段会自动去重。所以重复导入同一份课表不会产生重复数据。

## 构建（重要）

**本项目不在本地构建**，全部通过 GitHub Actions 编译。

```
推送到 main 分支  →  自动触发 .github/workflows/build-apk.yml  →  产出 APK
```

1. 打开仓库的 **Actions** 页面，等 `Build kobi APK` 跑完（首次约 3～6 分钟）。
2. 进入该次运行，在页面底部 **Artifacts** 下载 `kobi-apk`。
3. 解压得到 `kobi-debug.apk` 与 `kobi-release.apk`。

也可以在 Actions 页面手动触发（`workflow_dispatch`）。

### 为什么不在本地构建

本机没有安装 JDK、Android SDK 与 Gradle，且项目刻意不引入需要本地工具链的步骤。CI 用的是一套已验证可用的版本组合：

| 组件 | 版本 |
|---|---|
| JDK | 17 (temurin) |
| Gradle | 8.9 |
| Android Gradle Plugin | 8.7.3 |
| Kotlin | 2.1.0 |
| KSP | 2.1.0-1.0.29 |
| Compose BOM | 2025.01.00 |
| Room | 2.7.1 |
| ML Kit 中文文字识别 | 16.0.1（内置模型） |
| compileSdk / targetSdk / minSdk | 35 / 35 / 26 |

## 安装与首次使用

1. 把 APK 传到手机安装（需允许「安装未知来源应用」）。
2. 打开应用，**授予通知权限**。
3. 进「设置」页，按面板逐项完成引导：
   - 通知权限
   - **精确闹钟权限**（设置 → 应用 → 特殊应用权限 → 闹钟和提醒）
   - 省电策略设为**无限制**
   - 关闭电池优化
   - 允许**自启动**（小米：安全中心 → 应用管理 → 自启动）
   - 在最近任务里**锁定**本应用卡片
4. **设置学期开始日期**（第 1 教学周的周一）。不设置的话，周次会按第 1 周计算，周次过滤会导致课表显示不全。
5. 录入或导入课表。

> 这些设置不是可选项：漏掉任何一项，提醒都可能被延迟或根本不出现。

## 体积与启动

- **体积**：应用内置 ML Kit 中文文字识别模型（`com.google.mlkit:text-recognition-chinese`），模型随 APK 分发，因此**不需要联网、不依赖 Google 服务框架（GMS）**。代价是 APK 体积明显增大（artifacts 里两个 APK 合计约 30 MB）。构建时已限制只打包 `arm64-v8a` 与 `armeabi-v7a`，去掉手机用不到的模拟器架构。
- **启动**：冷启动不在数据库读取与闹钟重排上阻塞——重排推迟到首屏显示之后，并由数据变更、开机广播（`BOOT_COMPLETED`）、应用更新（`MY_PACKAGE_REPLACED`）三条路径覆盖。启动窗口背景与首屏背景同色，避免白屏跳变。

## 签名说明

`app/kobi.keystore` 是仓库内的**固定签名**（PKCS12，密码 `android`，别名 `androiddebugkey`），debug 与 release 都使用它。

这样做的目的是让 CI 每次构建出的证书指纹保持稳定，便于反复覆盖安装。**这是个人自用配置，不是安全的生产签名方案**——若要上架应用商店，必须换成你自己的正式签名并妥善保管密钥。

## 已知限制

1. **最重要的前提**：小米等厂商对「应用在后台发送本地通知」有系统级限制（默认可能拒绝，且用户设置里找不到开关）。本应用已按规范实现，但**能否按时送达必须在真机上实测确认**。若收不到，可考虑接入厂商推送通道。
2. 应用被杀后无法主动通知用户：厂商的省电机制可能清理后台进程，系统不提供「被清理时通知用户」的途径，只能靠上述白名单设置降低概率。
3. 导入解析器是容错式的：解析不了的行会被列出来并跳过（不中断导入），但不会智能纠错。字段归类靠文本特征启发式，遇到非常规写法（如把课程名写成一行纯数字、地点与课程名特征相近）可能归错，导入后请在列表里核对。
4. 图片识别是离线模型，识别结果**只是文本**，排版与字段仍需你核对；手写体、竖排、表格线遮挡的截图识别率低。
5. 作息表按常见作息内置（第 1 节 08:00 起、每节 55 分钟间隔、第 12 节 21:45），`.ics` 的钟点时间按它换算节次。你的学校作息不同的话，导入的节次会偏移。


## 通知的三种样式

| 样式 | 用法 |
|---|---|
| **动态倒计时** | 通知栏时间戳位置显示真实跳动的倒计时，由系统自刷新（不占用应用资源、不受通知更新限流影响） |
| **分段进度** | 每段代表一节课，标记当前时刻；用于「上课进行中」状态 |
| **自定义布局** | 内容区自绘成整周课表网格，用于总览 |

每条通知最多 3 个快捷操作按钮（Android 的硬限制）。
